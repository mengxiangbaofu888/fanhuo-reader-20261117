## 二、必开的令牌权限 —— 这一节是回答「需要开哪些权限」

### 2.1 建仓用（Personal Access Token，fine-grained）

| 权限 | 级别 | 干什么用 | 不开会怎样 |
|---|---|---|---|
| **Administration** | Read and write | **建仓库** | `POST /user/repos` 直接 403，仓建不出来 |
| **Contents** | Read and write | 推代码、建 tag、发 Release 附件 | 推不上去，发版没有 APK |
| **Workflows** | Read and write | 推送 `.github/workflows/*.yml` | 推工作流文件被拒：`refusing to allow a PAT to create or update workflow` |
| **Metadata** | Read（自动附带，必选） | 读仓库基本信息 | 所有 API 都 403 |

> 如果用的是 **classic token**，等价勾选是 `repo` + `workflow`。
> 现有的 `gho_` 令牌（`mengxiangbaofu888` 账号）已经有 `gist, repo, workflow`，跑本项目够用。

### 2.2 发版用（不用你开，CI 自带）

| 权限 | 谁用 | 干什么 |
|---|---|---|
| `contents: read` | `check-version` / `test` / `build` | 拉代码 |
| `contents: write` | `verify-and-release` | 建 Release、传 3 个 APK |
| `secrets.ANDROID_KEYSTORE_BASE64` 等 4 个 | `build` | Release 签名 |
| `secrets.GITHUB_TOKEN` | `verify-and-release` | GitHub 自动注入，**不需要手工配** |

### 2.3 签名密钥（4 个 Secrets，必须手工配）

```powershell
# 1. 先生成一个，一次生成终身用（换钥匙 = 用户不能覆盖升级）
& 'D:\github\downloads\tomato-apk-re-20261108\tools\jdk-17.0.20.1+1\bin\keytool.exe' `
  -genkeypair -v -keystore fanhuo-release.jks -keyalg RSA -keysize 2048 -validity 36500 `
  -alias fanhuo -storepass '<你的库口令>' -keypass '<你的key口令>' `
  -dname "CN=fanhuo-reader, O=fanhuo, C=CN"

# 2. 转 base64 填进 secret
$b64 = [Convert]::ToBase64String([IO.File]::ReadAllBytes('fanhuo-release.jks'))
$b64 | Set-Clipboard
```

然后在仓库 `Settings → Secrets and variables → Actions` 建四个：

| Secret 名 | 值 |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | 上面那串 base64 |
| `ANDROID_KEY_ALIAS` | `fanhuo` |
| `ANDROID_KEY_PASSWORD` | key 口令 |
| `ANDROID_STORE_PASSWORD` | 库口令 |

**没配也能构建**：CI 会打 debug 签名包（工作流里有 `::warning::`），能装能跑，
但两个版本之间不能互相覆盖升级。正式用一定要配。

## 三、发版流程

```powershell
Set-Location 'D:\github\projects\fanhuo-reader-20261117'
$node = 'C:\Program Files\nodejs\node.exe'

& $node scripts\bump-version.js patch     # 1.0.0 -> 1.0.1
# 手工在 CHANGELOG.md 加一节：## [1.0.1] - 2026-11-20
& $node scripts\check.js                  # 自检必过
& $node scripts\check-dart.js             # Dart 体检必过

git add -A
git commit -m "1.0.1：修 xxx"
git tag -a v1.0.1 -m "v1.0.1"
git push origin main
git push origin v1.0.1
```

推 tag 之后 CI 四关依次跑：

```
check-version  ──►  test  ──►  build（3 个 ABI 并行）  ──►  verify-and-release
   版本一致性       分析+测试     arm64 / armv7 / x64          验签 + 发版
   Node 自检         flutter
   Dart 体检        analyze/test
```

- 前两关各约 3～5 分钟，构建关每个 ABI 约 8～12 分钟（并行），总计 **15～25 分钟**
- 任何一关挂，后面的不出，Release 也不会建
- Release 里会出现 `fanhuo-reader-1.0.1-arm64.apk` / `-armv7.apk` / `-x64.apk`

### 手动跑（不发版，只出包）

仓库 `Actions → Release → Run workflow`，tag 输入框留空。
出的是 artifact，不是 Release。

## 四、下载与安装

- 手机直接开 `https://github.com/<用户名>/fanhuo-reader-20261117/releases`
- 绝大多数手机是 `arm64`；2018 年前的老机器选 `armv7`；模拟器选 `x64`
- 三个包的 `versionCode` 完全相同，所以**跨 ABI 覆盖升级不会失败**
- 装之前先卸载旧包（包名 `com.fanhuo.reader` 与上游 `org.mewx.wenku8_flutter` 不同，两个可以共存）

## 五、本地能不能出包

**这台机器不能。** 缺三样：

| 缺什么 | 现状 | 补法 |
|---|---|---|
| Flutter SDK | 没有，`flutter` / `dart` 都不在 PATH | 解压 `flutter_linux/windows_3.41.5-stable.zip`，约 1.2 GB |
| Android SDK | 只有 build-tools 36 (`aapt2` / `apksigner` / `zipalign`)，**没有 platform、没有 NDK** | `cmdline-tools` + `sdkmanager "platforms;android-36" "ndk;27.0.x"`，约 3 GB |
| JDK 17 | ✅ 有（`D:\github\downloads\tomato-apk-re-20261108\tools\jdk-17.0.20.1+1`） | —— |

所以本地只能做**静态检查**（`check.js` + `check-dart.js`），出包走 CI。
真要本地出包，装完上面两样后：

```powershell
$env:JAVA_HOME = 'D:\github\downloads\tomato-apk-re-20261108\tools\jdk-17.0.20.1+1'
$env:ANDROID_HOME = 'D:\github\downloads\android-sdk'
$env:PATH = "$env:JAVA_HOME\bin;$env:ANDROID_HOME\platform-tools;$env:PATH"
node scripts\prepare-base.js; node scripts\apply-patches.js; node scripts\sync-lib.js
cd _wenku_base
flutter pub get
flutter build apk --release --target-platform android-arm64
```

## 六、版本号规则

`VERSION` 是唯一来源，`versionCode = 主*10000 + 次*100 + 补`：

| VERSION | versionCode |
|---|---|
| 1.0.0 | 10000 |
| 1.0.1 | 10001 |
| 1.1.0 | 10100 |
| 2.0.0 | 20000 |

`scripts/bump-version.js` 会拒绝「新 versionCode 不大于旧值」的改动，
CI 的 `check-version` 会拒绝「VERSION 与 tag 不一致」。
