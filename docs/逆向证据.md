## 二、旷野书屋书源（需求二）

### 2.1 数据在哪

`com.yystv.www` 的 `assets/defaultData/bookSources.json`，**517 KB，133 条**。
字段与阅读（Legado）的 `BookSource` 18 字段逐一相同，`bookSourceType` 全是 0（文本源）：
可以直接在旷野、阅读、本项目之间互导。

同时抽出来的还有：
- `assets/defaultData/readConfig.json`（1227 B）—— 旷野自己那套排版
- `assets/defaultData/themeConfig.json`（580 B）
- `assets/defaultData/txtTocRule.json`（5967 B）—— TXT 目录规则
- `assets/extraData/*.json` 37 个（883 条书封墙数据，17 个分类）—— **不移植**，只是封面图运营数据

### 2.2 规则语法分布（决定了引擎要支持什么）

对 133 条逐条统计：

| 维度 | 数量 | 说明 |
|---|---|---|
| 有 `searchUrl` | 132 | 只有「如文网」缺 |
| `searchUrl` 是 `url,{json}` 的 POST 形 | 57 | body 里带 `searchtype=all&searchkey={{key}}` |
| `searchUrl` 是纯 GET | 76 | 大部分带 `?q={{key}}` |
| 规则里含 `@js:` | 20 | **引擎第一期不支持** |
| 规则里含 `<js>` | 45 | 同上 |
| 规则里含 `@css:` | 2 | 支持 |
| 规则里含 XPath（`//` 开头或 `@XPath:`） | 8 | 第一期不实现，抛出 `RuleUnsupported` |
| 规则里含 `{{...}}` 变量 | 133 | 支持 `{{key}}` / `{{page}}` / `{{page+n}}` |
| 依赖 `loginUrl` / cookie | 8 | 引擎不实现登录，这些源直接报错 |
| 带 `header` | 18 | 支持透传 |
| `bookSourceType != 0` | 0 | 全是文本源 |

**结论**：不依赖 JS 的 78 条可以直接跑；55 条要么补 JS 沙箱，要么放弃。
`lib/fanhuo/rule_engine.dart` 的 `needsJs()` 在解析前就拦，把「这个源不支持」明确抛出来，
而不是返回空列表让人以为「搜不到书」。

### 2.3 实测可达性（2026-11-17，本机直连）

用 `scripts/probe-sources.js` 同款逻辑逐源探首页：

| 状态 | 个数 | 含义 |
|---|---|---|
| 200 | 30 | 首页能打开 |
| 403 | 33 | Cloudflare / 反爬挑战 |
| 000（连不上） | 52 | 域名挂了 / DNS 不通 / TLS 失败 |
| 502 | 13 | 网关错误 |
| 404 | 3 | 路径没了 |
| 400 / 521 | 2 | 请求被拒 / Cloudflare 源站超时 |

**必须说清楚**：首页 200 不等于能搜到书，也不等于目录、正文能取。这只是个粗筛，
真正能不能用要一个个点开。33 个 403 里有一批是 Cloudflare 的 JS 挑战，
原生 HttpClient 过不去，除非上 WebView 或专门的过盾方案。

结果已写进 `data/kuangye-bookSources-133-probed.json` 的 `probeStatus` 字段，
`scripts/check.js` 会把它统计出来。

## 三、Wenku8_Flutter 作为底座（需求三）

### 3.1 为什么选它而不是继续拿阅读当底座

`D:\github\projects\fanqie-reader-20261111` 那轮用的是阅读（Kotlin/Java）当底座。
这一轮改用 Flutter，理由：

| 维度 | 阅读（Legado） | Wenku8_Flutter |
|---|---|---|
| 阅读页排版 | 46 字段，已经很强 | 也有，且滚动/分页/竖排三模式齐全 |
| 翻页动效 | 5 档 | 5 档（`ReaderPageEffect`），还多一个「纸页翻动」 |
| UI 可塑性 | Kotlin XML，改一次编译一次 | Flutter，热重载 + 直接抄设计 token |
| 书源引擎 | 自带完整 JS 引擎（Rhino） | 无（但可以自己写） |
| 许可证 | GPL-3.0 | GPL-3.0 |
| 构建 | Gradle + AGP，本机可跑 | 需要 Flutter SDK（本机没有，靠 CI） |

选 Flutter 的直接原因：**需求三说「我喜欢 wenku 的 UI」**。
把番茄的排版体系嫁接到 wenku 的 UI 语言上，改 `ThemeData` 和面板就够；
在阅读上做同样的事要动 Kotlin XML，成本高一个量级。

### 3.2 底座的关键事实

| 事实 | 值 | 出处 |
|---|---|---|
| 版本 | 0.4.1+88 | `pubspec.yaml` |
| Dart SDK | `^3.11.3` | `pubspec.yaml` |
| 行数 | 53,169 行 / 146 个 .dart | `lib/**` 统计 |
| 最大文件 | `pages.dart` 257 KB | —— |
| 阅读偏好模型 | `ReaderPreferences`（paper 5 档 / pageEffect 5 档 / mode 3 档） | `lib/reader_preferences.dart` |
| 阅读配色 | `ArchiveDesign`（奶白 `#F4F3EF` / `#FDFCFA` / 夜间 `#191919`） | `lib/archive_design.dart` |
| 玻璃材质 | `GlassPalette` + `shaders/analytic_glass.frag` | `lib/glass_palette.dart` |
| 网络 | 全部走 `MethodChannel('org.mewx.wenku8/legacy_api')` 原生桥 | `lib/legacy_transport.dart` |
| 上游保密 | 官方包需要私有的 `libcpp.so` API runtime，公开源码只有 reader preview | `.github/workflows/android-release.yml` |

**最后一条很关键**：上游刻意把「正文 API」放进了私有 runtime，
公开源码打出来的包只能读本地书。所以本项目**不能依赖上游的正文源**，
必须自带书源引擎（也就是需求二那部分工作），否则装上去是空壳。

### 3.3 上游网络域名（逆向确认）

从 `android/app/src/main/**/*.kt` 里抽出的全部 https 端点：

```
https://wenku8-relay.mewx.org/      ← 上游自建代理，实测 200（但只是落地页）
https://www.wenku8.net/             ← 官方站，实测 403（Cloudflare）
https://img.wenku8.com/image/       ← 封面 CDN，直连可达
https://app.3952039.xyz             ← 上游服务，实测 403
```

结论：上游的正文通道在本机这条网络上是断的。这也再次说明书源必须自建。
