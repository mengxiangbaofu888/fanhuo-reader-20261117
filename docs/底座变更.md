# 底座变更

本项目不改 Wenku8_Flutter 的既有代码（除包名与版本号），只**追加**文件：

```
_wenku_base/
├── assets/fanhuo/                 ← 从 data/ 拷进来
│   ├── kuangye-bookSources-133-probed.json
│   ├── fanqie-presets.json
│   └── ai-providers.json
└── lib/fanhuo/                    ← 从 lib/fanhuo/ 拷进来
    ├── fanqie_theme.dart          番茄配色与排版常量
    ├── fanqie_settings.dart       番茄式设置模型
    ├── fanqie_panel.dart          番茄式排版面板
    ├── book_source.dart           书源模型（18 字段）
    ├── rule_engine.dart           规则引擎（CSS / 变量 / POST）
    ├── multi_source_search.dart   多源并发搜书
    ├── ai_proofread.dart          AI 纠错（15 厂商 / 3 协议）
    └── ai_settings_page.dart      AI 设置页
```

## 被改动的三处既有文件

`scripts/apply-patches.js` 每次都从备份恢复再改，保证幂等：

| 文件 | 改什么 | 为什么 |
|---|---|---|
| `pubspec.yaml` | `flutter.assets` 里加 `assets/fanhuo/` | 不加就读不到书源 |
| `android/app/build.gradle.kts` | `namespace` / `applicationId` → `com.fanhuo.reader`，`wenkuAppLabel` → `番茄阅读 Pro` | 与上游包名区分，两个 app 能共存 |
| `pubspec.yaml` 的 `version` | `bump-version.js` 同步成 `VERSION+N` | 版本号唯一来源 |

**注意**：改 `applicationId` 之后，Kotlin 侧 `MainActivity` 等类的 `package` 声明如果跟着 `namespace` 走，
需要同步挪目录。上游的 Kotlin 包名是写死的 `org.mewx.wenku8_flutter`，`namespace` 改了但包名没改，
AGP 会报 `MainActivity not found`。所以 `apply-patches.js` **只改 `applicationId`，不动 `namespace`**：

```kotlin
// 上游
namespace = "org.mewx.wenku8_flutter"      // 不动：R 类与 Kotlin 包名要对上
applicationId = "com.fanhuo.reader"        // 改：安装包身份
```

这一条是**必须在 CI 上验证的第一件事**。本地没有 Flutter SDK 验证不了，
推上去第一次跑 `build` 关就能看到结论。

## 为什么用「追加文件 + 拷数据」而不是 patch

11-11 那轮用的是 patch，好处是可以精确改既有代码，坏处是底座一升级 patch 就废。
这一轮的改动几乎全是**新增**，只有三处单行替换，用脚本改字符串比 patch 稳：

- 底座升级到新版本时，`apply-patches.js` 的字符串替换有幂等保护（改过就跳过）
- 真要改既有逻辑（比如把 `FanqieReaderPanel` 挂进阅读页菜单），那时候再上 `patches/*.patch`

## 怎么把番茄面板挂进阅读页

上游阅读页在 `lib/reader_content.dart` + `lib/reader_chrome.dart`，
菜单栏在 `lib/reader_tools.dart`。挂法是加一个菜单项：

```dart
// 在阅读页的菜单里
IconButton(
  icon: const Icon(Icons.text_fields),
  onPressed: () => showModalBottomSheet<void>(
    context: context,
    backgroundColor: Colors.transparent,
    isScrollControlled: true,
    builder: (_) => FanqieReaderPanel(
      settings: fanqie,
      callbacks: FanqiePanelCallbacks(
        onChanged: (next) => state.setFanqieSettings(next),
        onOpenAiProofread: () => runAiProofreadChapter(),
      ),
    ),
  ),
)
```

`state.setFanqieSettings()` 落在 `LibraryState` 里，持久化键 `fanqie_reader_settings`，
存的是 `FanqieReaderSettings.toRecord()` 出来的 JSON 串。
**不动底座任何既有字段**，所以上游升级不会冲掉用户设置。

## 怎么把书源挂进搜索

上游的搜索走 `NovelRepository.search()`，实现是 `OfflineNovelRepository`
（先本机缓存，再 `LegacyWenkuRepository` 走原生桥）。

挂法是加一个**并列**的 repository，不替换上游：

```dart
final fanhuo = FanhuoSearchRepository(
  sources: BookSource.parseList(await rootBundle.loadString('assets/fanhuo/kuangye-bookSources-133-probed.json')),
  fetch: (request, {headers}) => http.post/Get(...),
);
// 搜索页给两个 tab：「文库」= 上游，「书源」= fanhuo
```

这样上游的离线缓存、听书、书架全都不受影响，书源搜到的书走另一个
`Novel` 适配（`bookUrl` 直接存，章节靠 `ruleToc` / `ruleContent` 现抓）。

## 目录对不上怎么办

`scripts/apply-patches.js` 里每一处字符串替换都带锚点，锚点找不到就直接退出并打印文件名。
遇到上游大版本升级导致锚点失效，按它打印的文件名手工看一眼，改完锚点再跑。
不要改成「找不到就跳过」——那会让 CI 静默出一个没注入数据的包。
